## 在每个 PR 上测试和验证

每当针对 `main` 分支打开 PR 时，会运行一个验证脚本，确保：

1. 更改已使用 ruff 格式化
2. 所有单元测试通过
3. 更改没有任何类型或 lint 错误。

查看 `.github/workflows/validate.yml` 文件以获取更多信息。

## 使用 Github Releases 构建 Docker 镜像

如果您使用 [Dockerhub](https://hub.docker.com/) 存储镜像，可以通过 Github Release 构建并推送镜像。此操作在 `.github/workflows/docker-images.yml` 文件中定义。

1. 为 Github Actions 创建一个 [Docker 访问令牌](https://hub.docker.com/settings/security)

<img src="/images/docker-access-token.png" alt="docker-access-token" />

2. 在您的 github 仓库中创建密钥变量 `DOCKERHUB_REPO`、`DOCKERHUB_TOKEN` 和 `DOCKERHUB_USERNAME`。这些变量由 `.github/workflows/docker-images.yml` 中的操作使用

<img
  src="/images/github-actions-docker-secrets.png"
  alt="github-actions-docker-secrets"
/>

3. 使用 Github Release 运行工作流

此工作流配置为在创建发布时运行。使用以下命令创建新发布：

<Note>

在运行前确认 `.github/workflows/docker-images.yml` 文件中的镜像名称

</Note>

<CodeGroup>

```bash Mac
gh release create v0.1.0 --title "v0.1.0" -n ""
```

```bash Windows
gh release create v0.1.0 --title "v0.1.0" -n ""
```

</CodeGroup>

<img
  src="/images/github-actions-build-docker.png"
  alt="github-actions-build-docker"
/>

<Note>

您也可以使用 `gh workflow run` 运行工作流

</Note>

## 使用 Github Releases 构建 ECR 镜像

如果您使用 ECR 存储镜像，可以通过 Github Release 构建并推送镜像。此操作在 `.github/workflows/ecr-images.yml` 文件中定义，并使用新的 OpenID Connect (OIDC) 方法请求访问令牌，而无需使用 IAM 访问密钥。

我们将按照此[指南](https://aws.amazon.com/blogs/security/use-iam-roles-to-connect-github-actions-to-actions-in-aws/) 创建一个 IAM 角色，该角色将被 github 操作使用。

1. 打开 IAM 控制台。
2. 在左侧导航菜单中，选择身份提供商。
3. 在身份提供商窗格中，选择添加提供商。
4. 对于提供商类型，选择 OpenID Connect。
5. 对于提供商 URL，输入 GitHub OIDC IdP 的 URL：https://token.actions.githubusercontent.com
6. 获取指纹以验证服务器证书
7. 对于受众，输入 sts.amazonaws.com。

验证信息与下面的截图匹配并添加提供商

<img src="/images/github-oidc-provider.png" alt="github-oidc-provider" />

8. 为提供商分配角色。

<img
  src="/images/github-oidc-provider-assign-role.png"
  alt="github-oidc-provider-assign-role"
/>

9. 创建新角色。

<img
  src="/images/github-oidc-provider-create-new-role.png"
  alt="github-oidc-provider-create-new-role"
/>

10. 确认 Web 身份已作为受信任实体被选中，并且身份提供商字段已填充 IdP。在受众列表中，选择 sts.amazonaws.com，然后选择下一步。

<img
  src="/images/github-oidc-provider-trusted-entity.png"
  alt="github-oidc-provider-trusted-entity"
/>

11. 为此角色添加 `AmazonEC2ContainerRegistryPowerUser` 权限。

12. 使用名称 `GithubActionsRole` 创建角色。

13. 找到角色 `GithubActionsRole` 并复制 ARN。

<img src="/images/github-oidc-role.png" alt="github-oidc-role" />

14. 创建由工作流构建的 ECR 仓库：`llm` 和 `jupyter-llm`。

<img src="/images/create-ecr-image.png" alt="create-ecr-image" />

15. 使用 `GithubActionsRole` ARN 和 ECR 仓库更新工作流。

```yaml .github/workflows/ecr-images.yml
name: 构建 ECR 镜像

on:
  release:
    types: [published]

permissions:
  # 用于 AWS OIDC 令牌访问，根据 https://docs.github.com/en/actions/deployment/security-hardening-your-deployments/configuring-openid-connect-in-amazon-web-services#updating-your-github-actions-workflow
  id-token: write # 请求 JWT 所需
  contents: read # actions/checkout 所需

env:
  ECR_REPO: [YOUR_ECR_REPO]
  # 使用 https://aws.amazon.com/blogs/security/use-iam-roles-to-connect-github-actions-to-actions-in-aws/ 创建角色
  AWS_ROLE: [GITHUB_ACTIONS_ROLE_ARN]
  AWS_REGION: us-east-1
```

16. 更新 `docker-images` 工作流以**不**在发布时运行

```yaml .github/workflows/docker-images.yml
name: 构建 Docker 镜像

on: workflow_dispatch
```

17. 使用 Github Release 运行工作流

<CodeGroup>

```bash Mac
gh release create v0.2.0 --title "v0.2.0" -n ""
```

```bash Windows
gh release create v0.2.0 --title "v0.2.0" -n ""
```

</CodeGroup>
