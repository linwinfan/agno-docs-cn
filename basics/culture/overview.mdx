想象一下，代理能够从每次交互中学习并将这些学习成果相互分享。
支持代理发现客户更喜欢带有代码示例的分步解决方案。
技术写作代理了解到"操作性思维"能产生更好的文档。
这些见解不应该丢失——它们应该成为共享文化的一部分，永远造福所有代理。文化将这些模式转化为可重用的规则，您的代理从第一天起就可以遵循。

## 文化如何工作

文化提供了一个共享知识层，代理在此存储适用于所有交互的通用原则、最佳实践和可重用见解。与存储用户特定事实（"Sarah 偏好电子邮件"）的记忆不同，文化存储对所有人都有益的通用知识（"始终提供具有明确后续步骤的可操作解决方案"）。

当代理完成任务时，它可以反思哪些方法有效，并将其提炼为文化知识。之后，当任何代理面临类似情况时，它会自动访问这种共享文化并应用这些学习成果。

<Tip>
**文化 ≠ 记忆：** 文化存储适用于所有交互的通用原则和最佳实践。[记忆](/basics/memory/overview) 存储用户特定的事实和偏好。将文化视为"我们在这里做事的方式"，将记忆视为"我对你的了解"。
</Tip>

<Note>
**注意：** 文化是一项实验性功能，可能会发生变化。当前目标是帮助代理在语调、推理和行为上保持一致。最终目标是将孤立的代理转变为一个活生生的、不断进化的集体智能系统。
</Note>

## 为什么要使用文化？

文化使智能能够复利增长。代理不是每次都从零开始，而是建立在集体经验之上：

- **一致性：** 所有代理遵循相同的沟通标准、格式规则和最佳实践
- **进化：** 随着代理学习什么有效，您的代理系统会随时间改进
- **效率：** 代理不会重复学习相同的教训

**使用案例示例：**
- 保持一致风格和结构的技术文档代理
- 应用经过验证的问题解决模式的客户支持团队
- 遵循组织编码标准的开发助手
- 遵守品牌语调和格式指南的内容生成

## 开始使用文化

设置文化非常简单：连接数据库并启用文化功能。以下是一个基本设置：

```python
from agno.agent import Agent
from agno.db.sqlite import SqliteDb

# Setup your database
db = SqliteDb(db_file="agno.db")

# Setup your Agent with Culture
agent = Agent(
    db=db,
    add_culture_to_context=True,  # Agent reads cultural knowledge
    update_cultural_knowledge=True,  # Agent updates culture after runs
)
```

启用这些标志后，您的代理会自动：
1. 在开始任务时加载相关的文化知识
2. 在推理和响应生成过程中应用这些知识
3. 在交互后进行反思
4. 根据所学内容更新或添加文化知识

## 文化管理的三种方法

Agno 根据您的需求提供了三种管理文化知识的方法：

### 1. 自动文化（`update_cultural_knowledge=True`）

每次代理运行后，系统会自动反思交互并更新文化知识。这是大多数生产用例的推荐方法。

```python
from agno.agent import Agent
from agno.db.sqlite import SqliteDb

db = SqliteDb(db_file="agno.db")

agent = Agent(
    db=db,
    add_culture_to_context=True,  # 读取文化
    update_cultural_knowledge=True,  # 自动更新文化
)

# 代理将从此次交互中学习
agent.print_response(
    "如何使用 Docker 设置 FastAPI 服务？",
    stream=True,
)
```

**最适合：** 希望代理根据有效方法持续改进其方法的生产系统。

### 2. 代理驱动的文化（`enable_agentic_culture=True`）

代理通过内置工具完全控制文化管理。它决定何时以及向文化知识库中添加什么内容。

```python
from agno.agent import Agent
from agno.db.sqlite import SqliteDb

db = SqliteDb(db_file="agno.db")

agent = Agent(
    db=db,
    add_culture_to_context=True,  # 读取文化
    enable_agentic_culture=True,  # 代理控制的文化工具
)
```

使用代理驱动的文化，代理配备了在对话过程中（而不仅仅是在完成后）管理文化知识的工具，当它认为相关时就会使用这些工具。

**最适合：** 代理需要在任务期间主动决定建立或更新哪些原则的复杂工作流。

### 3. 手动文化管理

使用 `CultureManager` 或直接实例化 `CulturalKnowledge` 对象来显式创建文化知识。非常适合播种组织标准。

```python
from agno.culture.manager import CultureManager
from agno.db.schemas.culture import CulturalKnowledge
from agno.db.sqlite import SqliteDb
from agno.models.anthropic import Claude

db = SqliteDb(db_file="agno.db")

# 选项 A：使用 CultureManager 和模型处理原则
culture_manager = CultureManager(
    db=db,
    model=Claude(id="claude-sonnet-4-5"),
)

message = """
所有技术指导都应遵循"操作性思维"：
1. 陈述目标 — 说明结果及其原因
2. 展示流程 — 清晰、可复现的步骤
3. 揭示陷阱 — 通常会失败的地方
4. 定义验证 — 如何确认其有效性
5. 闭环反馈 — 建议下一步迭代
"""

culture_manager.create_cultural_knowledge(message=message)

# 选项 B：手动添加文化知识（无需模型）
response_format = CulturalKnowledge(
    name="响应格式标准",
    summary="保持响应简洁、易扫描，并以可运行代码为先",
    categories=["communication", "ux"],
    content=(
        "- 以最少的可运行代码片段开头\n"
        "- 使用编号步骤描述流程\n"
        "- 以验证清单结尾"
    ),
    notes=["源自用户反馈"],
)

culture_manager.add_cultural_knowledge(response_format)
```

**最适合：** 播种初始组织原则、入职标准或所有代理都应遵循的品牌指南。

## 存储：文化存放的位置

文化知识存储在您连接到代理的数据库中。Agno 支持所有主要数据库系统：Postgres、SQLite、MongoDB 等。完整的列表请查看[数据库文档](/basics/database/overview)。

默认情况下，文化知识存储在 `agno_cultural_knowledge` 表中（对于文档数据库则是集合）。也可以配置自定义表名。如果该表不存在，Agno 会自动创建它。


```python
from agno.agent import Agent
from agno.db.postgres import PostgresDb

db = PostgresDb(
    db_url="postgresql://user:password@localhost:5432/my_database",
    cultural_knowledge_table="my_culture_table",  # 自定义表名
)

agent = Agent(
    db=db,
    add_culture_to_context=True,
    update_cultural_knowledge=True,
)
```

### 手动检索文化

您可以使用 `CultureManager` 手动检索文化知识：

```python
from agno.culture.manager import CultureManager
from agno.db.sqlite import SqliteDb

db = SqliteDb(db_file="agno.db")
culture_manager = CultureManager(db=db)

# 获取所有文化知识
all_knowledge = culture_manager.get_all_knowledge()
print(all_knowledge)

# 预览文化知识（为可读性截断）
for knowledge in all_knowledge:
    print(knowledge.preview())
```

## 文化知识数据模型

数据库中的每个文化知识条目包含以下字段：

| 字段 | 类型 | 描述 |
| ------------ | -------- | ------------------------------------------------ |
| `id` | `str` | 唯一标识符（自动生成） |
| `name` | `str` | 文化知识的名称/标题 |
| `content` | `str` | 原则/知识的主要内容 |
| `summary` | `str` | 知识的简要摘要 |
| `categories` | `list` | 分类（例如："communication"、"engineering"）|
| `notes` | `list` | 附加说明或上下文 |
| `metadata` | `dict` | 任意元数据（来源、版本等） |
| `input` | `str` | 生成此知识的原始输入 |
| `created_at` | `int` | 创建时间戳（纪元秒） |
| `updated_at` | `int` | 最后更新时间戳（纪元秒） |
| `agent_id` | `str` | 创建它的代理 ID |
| `team_id` | `str` | 关联的团队 ID |

## 最佳实践

1. **从手动播种开始：** 预先定义核心组织原则、沟通标准和最佳实践
2. **在生产中使用自动更新：** 让 `update_cultural_knowledge=True` 自然地处理演进
3. **定期审查：** 检查已积累的文化知识并根据需要进行优化
4. **保持文化专注：** 文化应包含通用原则，而不是特定任务的细节
5. **与记忆结合使用：** 使用文化表示"我们做事的方式"，使用记忆表示"我对你的了解"

## 常见用例

### 技术文档标准
```python
# 播种文档标准
doc_standard = CulturalKnowledge(
    name="文档标准",
    summary="所有文档遵循结构：示例 → 解释 → 验证",
    categories=["documentation", "engineering"],
    content=(
        "1. 从最小工作示例开始\n"
        "2. 解释关键概念和决策\n"
        "3. 提供验证步骤\n"
        "4. 链接到相关资源"
    ),
)
```

### 客户沟通语调
```python
# 定义沟通标准
comm_standard = CulturalKnowledge(
    name="客户沟通语调",
    summary="专业、富有同理心、以解决方案为导向",
    categories=["communication", "support"],
    content=(
        "- 首先确认客户的情况\n"
        "- 提供清晰、可操作的步骤\n"
        "- 除非必要，否则避免使用术语\n"
        "- 始终提供后续步骤或替代方案"
    ),
)
```

### 代码审查原则
```python
# 工程标准
code_review = CulturalKnowledge(
    name="代码审查标准",
    summary="关注可维护性、安全性和性能",
    categories=["engineering", "code-review"],
    content=(
        "- 首先检查安全漏洞\n"
        "- 验证错误处理是否全面\n"
        "- 确保代码具有自文档化特性\n"
        "- 在相关位置建议性能优化"
    ),
)
```
